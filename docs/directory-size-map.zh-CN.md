# 基于索引的目录空间图

File Size Analyzer 默认打开“目录空间图”，也可切回原“大文件”视图。
交互参考 [SpaceSniffer 的目录缩放](https://www.uderzo.it/main_products/space_sniffer/)，
数据来自已有文件索引，不触发新的文件系统扫描或内容类型探测。

* 默认显示两层：外层是当前目录的直属文件和目录，目录内部展示下一层。
* 单击查看大小、文件数、创建/修改时间；双击目录或按 Enter 进入。
* 面包屑、“上级目录”和图中 Backspace 可返回上层，浏览器前进/后退保留路径。
* 按目录分支配色，纯大小模式也有区分度。颜色不表示探测得到的文件类型。
* 总容量使用当前目录已保存的汇总，父目录与子项不重复相加。
* 零大小项目不占图形面积，但会在下方返回的项目列表中展示。

## 大索引行为

`GET /api/tools/size-tree?source=...&path=/.../&depth=2` 使用只读事务读取索引快照。
每次最多返回 600 个节点、展开 24 个目录、每个目录最多列出 80 个直接子项；
不查询整棵子树、不运行全源 `COUNT`，也不将全部文件传到浏览器。
每次请求有 5 秒数据库超时，切换目录会取消前一个浏览器请求。

其余已索引空间用独立方块展示，保持目录占比。未展开、小项目、隐藏或筛选掉的
内容可能包含在这一汇总中；大小和文件数沿用索引的统计口径。用户目录 scope、
数据源查看权限、访问规则及显示偏好会限制返回的条目名称和路径。

复用已有 `(source, parent_path)` 索引，无需新增覆盖全库的索引。
若单个目录直接包含数百万条记录，数据库仍需要在该目录范围内按大小选取前列，
此类目录可能超时；节点上限不代表所有 SQL 查询都恒定耗时。
索引初始化未完成时返回暂不可用，尚未建立目录索引时明确提示；扫描中的大小
来自最新保存的汇总，不能将其当作实时文件系统或 ZFS 快照统计。

## 验证

SQLite 和 PostgreSQL 测试覆盖两层边界、600 节点上限、过滤和取消请求。
HTTP 测试在未挂载的源路径上验证纯索引读取，并检查用户 scope、访问规则、
隐藏显示、扩展名过滤、路径越界与无查看权限。
前端测试覆盖父子面积不重复累计、未展示空间、零大小、极大大小差异、
目录进入/返回及取消旧请求后不覆盖新结果。

已完成的验证：

| 检查 | 结果 |
| --- | --- |
| SQL、索引和 HTTP 包的 Go race 测试（含 PostgreSQL 测试库） | 通过 |
| 前端完整测试 | 54 个测试文件、352 项测试通过 |
| 最终布局调整后的目录图、导航和 API 测试 | 9 项通过 |
| 前端类型检查、Biome/ESLint、翻译键检查和相关样式检查 | 通过 |
| 完整 Docker 镜像构建 | `linux/amd64` 构建成功 |
| 浏览器验证 | 两层展示、双击进入、返回上层、选中详情、小文件合并及旧视图切换通过 |

界面验证使用独立生成的测试数据。上述结果验证功能正确性，未对大规模生产索引做性能基准。
